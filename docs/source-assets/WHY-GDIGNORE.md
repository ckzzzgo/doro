# 为什么 docs/ 下有个 .gdignore

`docs/` 里放的是文档、README 用图和不参与运行的草稿素材。它们不该被打进安装包。

一开始我用的是 `export_presets.cfg` 的 `exclude_filter`，试了两种写法都没成功：

- `docs/*` —— 完全没起作用。过滤器匹配的是带 `res://` 前缀的完整路径，前缀对不上。
- `*docs/*` —— 只挡掉一部分，pck 里仍残留 27 个 `res://docs/...` 资源。

而且我第一次「验证通过」是错的：当时扫描只读了 pck 的前 40 MB，那些路径恰好在更后面。
教训是 —— 扫描前 N 字节只能证明「某个东西在包里」，不能证明「不在」。

正确的机制是 `.gdignore`：目录里放这个空文件，Godot 会**完全跳过整个目录**，
不导入、不打包，编辑器里也看不到。这正是我们想要的语义，而且不依赖过滤器的
通配符怎么解释。

发版脚本 `tools/build_release.ps1` 里加了一条全量扫描的检查，如果 `res://docs/`
再次混进 pck 会直接让构建失败。
